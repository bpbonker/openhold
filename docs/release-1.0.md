# Release 1.0: definition and progress

Release 1.0 is the first version an organisation can run in production: one site with Windows sign-in, backups,
its existing drawings imported, an item master issuing part numbers from its own scheme, and its ERP fed
automatically. An item is done only when it's built, tested (automated where possible) and documented.

| # | Area | Done when | State |
|---|---|---|---|
| 1 | **Production hosting** | Server runs as a Windows service with HTTPS and Windows sign-in (tested against a real domain); install and upgrade script; backup and restore scripts with a rehearsed restore. | Built: service install, HTTPS settings, Windows sign-in tested against a real domain, backup rehearsal passed. Still to do: a full production install over HTTPS. |
| 1a | **Sign-in and accounts** | Windows (Kerberos), organisation accounts (OpenID Connect) and Openhold accounts (password plus TOTP two-factor), side by side. Administrators define users, require or reset two-factor, disable accounts (immediately, every method), unlock and sign out sessions. Privileges are granted to groups. Lockout, session expiry and audit of every sign-in. | Done (OpenID Connect sign-in from the desktop still to add; the server accepts it). |
| 1b | **Security programme (SOC 2-aligned)** | Controls mapped to the SOC 2 Trust Services Criteria (CC6 access, CC7 operations/monitoring, CC8 change, A1 availability, C1 confidentiality): HTTPS only, security headers, rate limiting, least privilege, access-review report, append-only audit with retention, dependency vulnerability scan and SBOM, secrets kept out of the repository, incident-response and key-rotation procedures. Documented in SECURITY.md with each control's evidence. | Done (SECURITY.md, security-check.ps1). |
| 1c | **Complete backups** | One backup job covers the databases, the file store, server settings, the token-signing key and logs, for the authority and each site; encrypted, kept off the server, with retention; a restore script and a rehearsed restore. | Done (a full database dump per run); restore rehearsed into a new database. Point-in-time restore (WAL archiving) is not built. |
| 2 | **Item master and catalogue** | Items with universal numbers (check digit, issued centrally), classification with attributes, approved manufacturers with duplicate checks, legacy cross-references, links to files, Draft → Released → Obsolete with a part-librarian group; Catalogue window in Explorer; "Adopt into catalogue" for legacy parts. | Done (server, tests, Catalogue window, Item Classes administration, Add to Catalogue). |
| 3 | **ERP connectors** | Connector interface and per-company connections; item sync as background jobs with retries; a CSV/file connector as the reference; simPRO connector built to its API. | Done. | 4 | **Legacy import** | Bulk import of a folder tree with references (Inventor, DWG xrefs, AutoCAD Electrical projects), properties and revisions, into a read-only Legacy area; dry run with a report first. | Done (OpenholdImport), tried on copies of real project folders. |
